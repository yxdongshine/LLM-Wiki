# Ingest：原始资料摄取

## 目标

维护当前 Obsidian LLM Wiki 的 Inbox → Compile → Archive 流程：

1. 从 `raw/` 读取尚未归档的原始资料。
2. 将资料提炼为可追溯、可链接的中文知识页面。
3. 增量更新 `wiki/index.md` 与 `wiki/log.md`。
4. 仅在单个源文件完整处理成功后，将其移动到 `raw/99-archive/`。

不得修改源文件内容，不得读取或摄取任何归档目录中的既有内容（向归档目录写入移动后的源文件是唯一例外）。

## 当前仓库结构

`raw/` 当前按项目类型组织，包含了各种资料：

- `raw/01-公司开发规范/`
- `raw/02-项目资料/`
- `raw/99-archive/`：规范归档目录，始终排除

知识输出目录：

- `wiki/sources/`：每个原始文件（或源码目录整体）对应的来源摘要
- `wiki/entities/`：人物、公司、模型、工具、产品
- `wiki/concepts/`：理论、框架、技术、方法论
- `wiki/syntheses/`：跨来源综合分析；普通 ingest 不主动创建，除非资料本身需要跨来源归纳
- `wiki/index.md`：全局知识索引
- `wiki/log.md`：追加式操作日志
- `assets/`：从资料中提取且确有知识价值的图片或媒体

不要假定存在 `CLAUDE.md`。本文件中的页面契约即 ingest 的执行规范；如与 `wiki/templates/` 旧模板冲突，以本文件契约为准。

## 触发与输入范围

### `/ingest`

递归扫描 `raw/` 下的待处理文件，但在遍历入口处排除：

- `raw/99-archive/**`
- `raw/999-archive/**`（如存在，仅作旧归档兼容排除区）
- `raw/98-活源/**`（动态源 git 工作副本，由 `/sync` 管理；对活源显式运行 `/ingest` 时应提示改用 `/sync`）
- 隐藏文件、临时文件和系统生成文件（如 `.DS_Store`）
- 构建产物目录：`build/`、`target/`、`node_modules/`、`out/` 及 `.class`、`.jar` 等编译产物

先生成稳定的待处理清单，再逐个执行流水线。一个文件失败不得阻止已成功文件正常完成，但失败文件不得归档。

**源单元判定**（避免逐文件建页爆炸）：

- 普通文档（`.md`、`.txt`、`.pdf`、`.docx`、`.xlsx`、`.pptx` 等）：一个文件 = 一个源单元。
- 源码工程或脚本目录（如整套 `.java`/`.scala` 工程、批量 SQL 目录树）：**整个目录 = 一个源单元**，建一个 Source 页，不逐文件建页。扫描时读取目录结构、README 和代表性文件来提炼，不要求读完每个源文件。
- 媒体与杂项（`.png`、`.eddx`、`.xmind`、`.mp4.zip` 等）：不单独作为源单元；确有知识价值的图片移入 `assets/` 并在相关 Source 页引用，其余随目录归档。

### `/ingest <path>`

- 接受 `raw/` 下的单个文件或目录。
- 目录输入采用与 `/ingest` 相同的递归、排除和源单元判定规则。
- 如果路径位于任一归档目录，立即停止并说明该路径禁止处理。
- 如果路径不存在、超出 `raw/`，或指向 `wiki/` 页面，不得猜测其他路径。



## 摄取流水线

对每个源单元按以下顺序执行。每个源单元是独立事务：页面、索引和日志全部成功后才能归档。

### 1. 预检与去重

记录源单元的原始相对路径、文件名（或目录名）、扩展名和所属主题目录。

处理前检查：

- `wiki/sources/` 是否已有 `sources` 指向该原始路径的 Source 页面。
- `wiki/log.md` 是否已有该路径的成功 ingest 记录。
- 源单元类型：git 仓库（含 `.git`）默认按 `live` 处理；其余按 `static`/`tracked`（由 Source 页 `update_policy` 决定）。
- 源文件是否为空、损坏或无法读取。

如果资料已摄取，不重复生成页面；报告现状，并仅在能够确认知识输出完整时处理遗漏的归档动作。



### 2. 读取资料

- `.md`、`.txt`：按 UTF-8 优先读取完整文本。
- `.pdf`：提取正文、标题、章节结构和页数。扫描版 PDF 无法提取正文时，尝试 OCR；仍失败则只创建"待补充"Source 页面，记录文件元数据与失败原因，且不归档。
- `.docx`、`.xlsx`、`.pptx`：使用可用的结构化读取工具提取正文与表格。
- 源码目录：读取目录树、README、构建配置和代表性源文件。
- 其他格式：使用可用的结构化读取工具。无法可靠读取时报告，不得编造内容，也不得归档。

对较长 PDF 按章节或页段处理，最后合并去重，避免只总结开头部分。



### 3. 提炼知识

使用简体中文提取：

- 核心主旨：资料解决什么问题，给出什么结论。
- 关键要点：保留定义、机制、步骤、条件、优缺点和案例。
- Entities：人物、组织、模型、工具、平台、产品。
- Concepts：理论、架构、算法、技术、方法论。
- 来源定位：能获得页码或章节时，在关键结论后保留定位信息。

只创建有持续复用价值的 Entity 和 Concept 页面。不要为普通词、章节标题或仅出现一次且无解释的名词建页。



### 4. 创建或更新 Source 页面

文件名使用**中文命名**，格式为 `{主题}-{资料名}.md`，与现有来源页保持一致，例如：

- `公司开发规范-招商城科数据项目指引.md`
- `CDP迁移项目资料.md`
- `cdp-engine源码.md`（源码目录整体作为源时，用工程名）

命名规则：

- 无空格，避免 `/ \ : * ? " < > |` 等特殊符号。
- 原始文件名只有序号（如 `1.pdf`）时，必须加入主题目录信息避免重名，例如 `LLM入门-01.md`。
- 英文专名（如 CDP、OneID）保留原文，不强行翻译。

页面格式：

```markdown
---
title: "资料标题"
type: source
tags: [来源, 主题标签]
sources: ["raw/原始相对路径/文件.pdf"]
last_updated: YYYY-MM-DD
---

# 资料标题

## 核心摘要
[3-5 句话说明资料主题、关键结论和适用范围]

## 关键要点
- [重要知识点]

## 关联连接
- [[实体页面名]] - 关联实体
- [[概念页面名]] - 关联概念
```

即使源文件随后归档，`sources` 仍记录摄取时的原始路径，确保来源身份稳定。可在正文补充归档后路径。



### 5. 增量维护 Entity 与 Concept

目标目录和命名（与现有页面保持一致）：

- Entity → `wiki/entities/`，有通用英文名或缩写的用原文（如 `OpenAI.md`、`OneID.md`），否则用中文（如 `招商城科.md`）
- Concept → `wiki/concepts/`，有通用英文术语或缩写的用原文（如 `RAG.md`），否则用中文（如 `注意力机制.md`）

所有页面必须包含以下 Frontmatter：

```yaml
---
title: "页面标题"
type: entity | concept
tags: [标签]
sources: ["raw/原始相对路径/文件.pdf"]
last_updated: YYYY-MM-DD
---
```

页面不存在时创建；页面存在时先完整读取，再执行增量合并：

- 保留已有有效内容和来源。
- 只添加新信息，避免同义重复。
- 将本次源路径加入 `sources`，不得删除旧来源。
- 更新 `last_updated`。
- 在 `## 关联连接` 中加入 Source 页面和真实存在的相关页面。

每个页面都必须有 `## 关联连接`。不要创建无法与 Source 或其他知识页建立有效关系的孤岛页面。

### 6. 处理知识冲突

如果新资料与现有页面存在实质冲突：

1. 暂停当前文件的后续写入和归档。
2. 明确报告冲突页面、旧说法、新说法及各自来源。
3. 等待用户选择：
   - 保留双方，在页面添加 `## 知识冲突`
   - 采用新说法，并保留旧说法的变更说明
   - 放弃当前文件的摄取
4. 得到决定后再继续。

不得静默覆盖，也不得把措辞差异误判为知识冲突。

### 7. 同步全局索引

`wiki/index.md` 已存在且为中文结构（概念索引 / 实体索引 / 资料来源索引 / 综合分析索引 / 最近更新）。**沿用现有结构增量登记**，不要重建骨架：

- 将新增页面登记到对应中文区块，格式统一为：`- [[页面名称]] — 一句话说明`
- 更新「最近更新」区块，摘记本次摄取。
- 更新时去重，保持现有条目与分类结构不变。不要登记尚未成功写入的页面。
- 仅当 `wiki/index.md` 不存在时，才初始化中文骨架（概念索引 / 实体索引 / 资料来源索引 / 综合分析索引 / 最近更新）。



### 8. 追加操作日志

`wiki/log.md` 只能追加，不能覆盖历史；存量条目（含早期 `[入库]` 格式）一律不动。每个源单元记录一次结果，新条目格式：

```markdown
## [YYYY-MM-DD] ingest | 摄取 <源文件名或目录名>
- **来源**: `raw/原始相对路径`
- **变更**: 新增 [[Source页面名]]；更新 [[页面名]]；同步 [[index]]
- **归档**: `raw/99-archive/对应相对路径`
- **冲突**: 无
```

失败或暂停时也记录原因，但不得写成成功归档。



### 9. 归档源文件

`update_policy: live` 的活源（git 仓库）**不归档**，无论条件如何，保留在 `raw/98-活源/`。其余源仅当以下条件全部成立时归档：

- Source 页面已成功创建或确认完整存在。
- 需要的 Entity、Concept 页面已成功创建或更新。
- `wiki/index.md` 已同步且无重复登记。
- `wiki/log.md` 已追加成功记录。
- 本次摄取没有待处理冲突。

如果 `raw/99-archive/` 或对应主题子目录尚不存在，在首次成功归档时创建它们。

在 `raw/99-archive/` 下保留源文件相对于 `raw/` 的目录结构。例如：

`raw/02-项目资料/CDP迁移/CDP工作流迁移.md`

移动到：

`raw/99-archive/02-项目资料/CDP迁移/CDP工作流迁移.md`

如果目标同名文件已存在，不得覆盖。比较文件后报告重复，或使用可追溯的重命名方案并在日志中记录。

`raw/999-archive/`（如存在）只作为旧归档兼容排除区；不要读取、迁移或重新摄取其中内容。

## 完成标准

结束前逐项确认：

- 未读取 `raw/99-archive/`（及如存在的 `raw/999-archive/`）中的任何既有内容。
- 未修改或删除源文件内容。
- 每个成功摄取的资料都有 Source 页面和可追溯的 `sources`。
- 新增知识页 Frontmatter 完整，并包含 `## 关联连接`。
- `wiki/index.md` 已同步且没有重复条目。
- `wiki/log.md` 已追加，历史记录未被重写。
- 只有完整成功且无冲突的源单元被移动到 `raw/99-archive/`。
- 对失败、跳过、重复和冲突文件给出清晰汇总。
