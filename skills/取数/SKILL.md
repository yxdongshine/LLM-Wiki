# 取数：数仓取数需求 SQL 工作流

## 目标

把取数类需求转化为**有证据、可交付**的 SQL，核心原则：**先查现网有没有现成封装表，而不是从零设计链路**。保证：

1. 优先复用现网 DWD/ADS 封装表，其次才允许 ODS 手工拼链路。

2. 每个字段都能指到 L1 证据（DDL 注释 / 现网脚本原文 / 数据字典 / 主人口述）。

3. 口径对齐现网同类统计脚本（消耗榜、折现周报等），不自创。

4. 查无实据的字段，允许「留空/降级」为合法交付，不强行补替代数据源。

   

## 触发方式

- `/取数 <需求>`
- "这个需求查哪个表？"
- "帮我写荟豆余额/消费的取数 SQL"
- "统计某指标，怎么取数？"
- "写一段 SQL 取 X 数据"



## 固定七步 SOP（治本）

```
① 现网资产盘点（第一步，不是设计）
   拿需求关键词（消费明细/回收明细/交易流水/余额…）检索现网，
   优先查 DWD/ADS 层有没有现成封装表
   │
   ├─ 有现成表 ──→ 跳 ② 确认取数方案
   │
   └─ 无现成表 ──→ ③ 设计链路（仅允许 ODS）
        │
        └─→ 对照现网口径核对（有无同类脚本在用同样取数）
   │
② 确认取数方案（闸门1 🆕）—— 展示表 + 字段清单 + 证据等级，等用户确认
   │
③ 设计链路（仅当无现成表时）
   │
④ 确认输出结构（闸门2 🆕）—— 明细/汇总/粒度/时间范围，等用户确认
   │
⑤ 验字段 + 写 SQL：DESC 表 / SELECT * LIMIT 1，以落库名为准
   │
⑥ 确认交付形式（闸门3 🆕）—— SQL脚本/Excel/CSV + 归档路径，等用户确认
   │
⑦ 交付归档
```

---

### ① 现网资产盘点（关键）

- 用需求中的业务词（明细/汇总/回收/发放/余额/流水）在 `raw/98-活源/` 现网脚本目录检索表名与脚本名。
- **表名语义匹配需求时，必须完整读它的 DDL，判断它是否就是答案**（"积分回收明细表"≈"消费明细"）。
- 优先找现网已封装的明细/汇总表，其次才考虑 ODS 源表拼接。
- 无现成表时，才进入③设计链路。

---

### ② 确认取数方案（闸门1，强制，不可跳过）

**⚠️ 资产盘点完成后，必须先展示「取数方案」并等用户明确确认，才允许进入后续步骤。绝不跳过确认直接写 SQL。**

#### 取数方案必须包含：

```
## 取数方案确认

### 使用表
| 表名 | 层级 | 用途 | 证据 |
|------|------|------|------|
| xxx  | DWD/ADS/ODS | 主表/辅助 | DDL/脚本路径:行号 |

### 字段清单
| 需求字段 | 落库名 | 来源表 | 证据等级 | 备注 |
|----------|--------|--------|----------|------|
| 用户ID   | one_userid | xxx | L1（DDL注释） | |
| 消费金额 | <?> | - | 待确认 | 需查消费明细表 |

### 待确认/留空字段
- 字段A：查无实据，建议留空
- 字段B：可选表X或表Y，待确认口径

### 口径对齐
- 参照现网脚本：xxx.sql（路径:行号）
- 金额公式：xxx

> ⏳ 请确认以上取数方案，确认后继续
```

#### 确认闸门规则（硬性）

**只有用户出现以下明确确认措辞之一，才允许继续：**
- 明确说"确认"、"可以"、"没问题"、"继续"、"就这么办"
- 或明确指示修改某项后继续（如"表X换成表Y，其他没问题"）

**以下情况一律视为未确认，必须停在当前步骤：**
- 模糊指令："好"、"OK"、"嗯"（无明确执行指向）
- 只提供参数/表名，未说确认
- 回答与方案无关的问题

---

### ③ 设计链路与口径核对

- 只有无现成表时才拼链路，且拼完必须对照现网同类脚本（消耗榜、ADS 周报等）核对取数表、过滤条件、金额公式。
- 金额类字段必须查清**来源公式**，不能只看字段名（例：`recived_point = SUM(used_points * point_rate)` 分摊口径，非 `receive.points`）。

---

### ④ 确认输出结构（闸门2，强制，不可跳过）

**⚠️ 取数方案确认后，必须先确认输出结构，再动手写 SQL。不确认结构直接写 SQL 容易产出不符合预期的结果。**

#### 输出结构必须确认：

```
## 输出结构确认

### 输出类型
- [ ] 明细表（逐行原始记录）
- [ ] 汇总表（聚合后的统计结果）

### 输出粒度
- 按用户 / 按天 / 按月 / 按业态 / 其他：___

### 时间范围
- 起止日期：YYYY-MM-DD ~ YYYY-MM-DD
- 或：最近 N 天 / 全量历史

### 排序/分页
- 排序字段：___
- 是否分页：是 / 否，每页 N 条

> ⏳ 请确认以上输出结构，确认后开始写 SQL
```

#### 确认闸门规则（同闸门1）

- 明确确认措辞 → 继续
- 模糊指令 → 停在当前步骤

---

### ⑤ 验字段 + 写 SQL

- 写 SQL 前 `DESC 表` 或 `SELECT * FROM 表 LIMIT 1`，确认字段落库名。
- **字段以落库名为准**，别名/相似名不算数（例：落库 `one_userid` ≠ 宽表 `one_user_id`）。
- 每个字段必须能指到证据坐标（脚本路径:行号 / 字典 sheet:行号 / 主人口述）。
- 指不到的按 AGENTS.md「事实依据规则」列为待确认或留空，不编造。

---

### ⑥ 确认交付形式（闸门3，强制，不可跳过）

**⚠️ SQL 写完后，交付前必须确认最终交付形式。不确认直接交付可能产出不符合预期的格式。**

#### 交付形式必须确认：

```
## 交付形式确认

### 交付物类型
- [ ] SQL 脚本文件（归档到 docs/scripts/）
- [ ] Excel 导出（含导出语句）
- [ ] CSV 导出
- [ ] 其他：___

### 归档路径
- SQL 脚本：docs/scripts/<脚本名>.sql
- 知识沉淀：wiki/syntheses/<综合页>.md

### 是否同步需求文档
- [ ] 是，更新 raw/00-requirement/ 下对应需求文档
- [ ] 否，仅交付 SQL

> ⏳ 请确认以上交付形式，确认后交付归档
```

#### 确认闸门规则（同闸门1）

- 明确确认措辞 → 交付归档
- 模糊指令 → 停在当前步骤

---

### ⑦ 交付归档

- 真实交付 SQL 按脚本名存 `docs/scripts/`（如 `荟豆取数-需求2消费明细.sql`）。
- 需求 + 代码实现一体化归档到 `wiki/syntheses/`（如 [[荟豆取数需求与实现]]）。
- 若跨多页形成可复用方法论，另存综合页（如 [[数仓取数SQL优化方法论]]）。
- 同步 `wiki/index.md`（综合分析索引）与 `wiki/log.md`（追加 ingest/sync 记录）。

## 证据分级（AGENTS.md 规则，强制）

- **L1 权威**：DDL 注释、现网脚本原文、数据字典、主人口述 → 可直接用于 SQL。
- **L2 可追溯推断**：由 L1 推导，需标注依据。
- **L3 无依据猜测**：**禁止**进入 SQL 或结论，只能列为待确认。



## 决策准则

- **降级合法化**：需求字段查无实据 → 默认「留空/降级」是合法结论，可交付；强行找替代字段补位才是错误。
- **优先复用现网口径**：现网已有同类统计脚本时，对齐其取数表与过滤条件。
- **不因输出完整性牺牲准确性**：留白优于填充，`<?>` 占位符优于编造字段。



## 禁止事项

- **禁止**先设计链路后查现网——必须先做现网封装表盘点。
- **禁止**跳过任何一个确认闸门（②④⑥），即使处于"你说我干"的主动执行模式也必须等用户明确确认。
- **禁止**在用户未确认取数方案时开始写 SQL。
- **禁止**引用某脚本作证据却不完整读其 DDL。
- **禁止**字段用别名/相似名冒充落库字段。
- **禁止**编造字段名/表名/口径；L3 一律不进 SQL。
- **禁止**跨表字段串味（形近表各自查证）。
- **禁止**用替代数据源掩盖"字段无实据需降级"的正确结论。



## 完成标准

- 已做现网封装表盘点，有现成表则已复用。
- ✅ **三个确认闸门均已通过**——取数方案（②）、输出结构（④）、交付形式（⑥）均已获用户明确确认。
- 每个字段都有 L1 证据坐标或明确标注待确认/留空。
- 口径已对齐现网同类脚本。
- 交付 SQL 已归档 `docs/scripts/`，知识已沉淀 `wiki/syntheses/`。
- 未编造任何字段/表/口径。
